# ADR-008: Synthea Companion Source Strategy

## Status

Accepted

## Context

FHIRBridge will begin with custom synthetic legacy-style data from multiple fictional healthcare systems.

However, the project also needs exposure to native FHIR data so that it can learn FHIR ingestion, resource relationships, validation, storage, and analytics patterns.

Synthea can generate realistic synthetic patient records and FHIR bundles, making it useful as a companion source.

## Decision

FHIRBridge will use Synthea as a Phase 1 companion source, not as the primary source strategy.

Synthea will support:

- Native FHIR ingestion
- FHIR bundle exploration
- Resource relationship learning
- Validation comparison
- Testing and future analytics scenarios

## Architecture Principle

Synthea is one source among many.

FHIRBridge must remain focused on multi-source healthcare interoperability, including messy legacy data, claims data, lab data, and future FHIR-native data.

## Synthea Role in Phase 1

Synthea will be used to understand:

- Patient resources
- Encounter resources
- Condition resources
- Observation resources
- Medication resources
- DiagnosticReport resources
- Organization, Practitioner, and Location relationships

## Comparison Strategy

FHIRBridge may compare:

- FHIR generated from custom legacy mappings
- Native FHIR generated by Synthea

This comparison will help identify:

- Mapping gaps
- Resource relationship differences
- Validation issues
- Terminology differences
- Data completeness differences

## Future Uses

Synthea may support future work in:

- SQL on FHIR
- OMOP comparison
- Population health analytics
- Quality measurement scenarios
- AI-assisted workflow experiments
- Cloud deployment testing

## Rationale

Synthea accelerates FHIR learning without replacing the core project goal.

The main goal of FHIRBridge remains learning how fragmented healthcare data becomes trusted canonical FHIR data.

## Consequences

FHIRBridge must maintain separate storage for Synthea FHIR bundles.

Synthea data should be treated as native FHIR input, not legacy data requiring mapping.

Synthea should be used for learning, testing, comparison, and validation.
